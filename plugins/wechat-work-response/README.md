# WeCom Response Plugin

This plugin is the asynchronous response side of the WeCom integration. It is
packaged separately from the trigger because Dify does not allow trigger and
tool providers in the same plugin manifest.

The plugin provides two normal workflow tools. Both accept the unique
`response_url` emitted by the trigger event and deliver the result to WeCom.
The URL is carried in each tool invocation, so the response plugin has no
static backend URL or copy of the trigger's callback secrets.

- `wechat_work_reply` accepts `response_url`, `message_id`, and `content`.
- `wechat_work_status` accepts the same fields plus a non-empty `status`.

Map `response_url` and `message_id` from the WeCom trigger outputs. The
`content` and `status` values can be supplied by the workflow or generated by
an LLM node. Multiple tool invocations can send multiple messages for one
event.
